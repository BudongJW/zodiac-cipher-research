## 2. 工具包 `zkc`

```
zkc/
├── cipher.py      密文加载（按原件行结构）、网格坐标
├── stats.py       多重度、同构模式、周期双字母重复、IoC、熵、置换检验、符号重合表
├── transpose.py   (dr, dc) 抽取读取、正/逆换位、Z340 已发表换位方案（含全部异常）
├── keys.py        由对齐明文推导密钥（检测冲突）、应用密钥、准确率
├── ngram.py       字母 n-gram 模型：加载 AZdecrypt 格式（二进制 / 文本 / .gz）或由语料自建
├── corpus.py      内置英文语料：Python 标准库文档字符串 + pydoc 文档（约 165 万字母）
├── solver.py      同音替换求解器：模拟退火 + 热浴采样，向量化计算 26 个候选字母，多进程重启
├── reproduce.py   Z408 / Z340 的确定性复现与盲解评估
├── console.py     控制台 UTF-8 输出
└── __main__.py    命令行
scripts/
└── z340_transposition_scan.py   Z340 候选换位 × 求解器扫描
tests/             单元测试（python -m unittest discover -s tests；慢速测试需 ZKC_SLOW=1）
```

常用命令：

```bash
python -m zkc verify                          # 确定性复现 Z408 / Z340
python -m zkc overlap                         # 符号重合表
python -m zkc stats z340 --shuffle 20000      # 统计量 + 置换检验
python -m zkc solve z408                      # 盲解（默认内置 4-gram 模型、8 次重启）
python -m zkc solve z340 --model <n-gram 文件>  # 使用外部 n-gram 模型
```

依赖：Python ≥ 3.10、numpy。

### 求解器的目标函数

```
score = mean_ngram × (H / 4.1) ^ w
```

`mean_ngram` 为明文平均 n-gram 分数，`H` 为明文字母熵（bits），4.1 为英文典型字母熵，`w` 为熵权重（默认 2.0）。熵项用于抑制同音替换中的“退化解”。调参记录：`w = 0.75`（AZdecrypt 对其自有模型的默认值）配合内置模型时，退化解（H ≈ 3.2–3.6）得分高于真实明文；`w ≥ 1.5` 起真实明文排在前面，故取 2.0。

## 3. 确定性复现

### 3.1 Z408

由 `data/solutions/z408_plaintext.txt` 与密文逐位对齐推导出的密钥：54 个符号，每个符号只对应一个字母（无冲突）。已知明文中的错误（如 DANGERTUE、末尾 18 字符）属于 Harden 密钥本身，予以保留。

### 3.2 Z340

1. 由“密文位置”的明文推导密钥：63 个符号，无冲突。
2. 按已发表方案读取（`zkc.transpose.z340_order()`）：
   - 第 1–9 行、第 10–18 行：各自在 9×17 网格上做 (1, 2) 抽取（下 1 行、右 2 列，越界回绕）；
   - 第 2 段的 LIFEIS 六格（段内第 1 行第 12–17 列）抽取时跳过，置于该段末尾；
   - 第 2 段段内第 6 行（全局第 15 行）第 17 列的符号视为位于第 4 列（“H 移位”）；
   - 第 19–20 行按行读取，片段 EFIL / EB / NA / ENO / NI / ECIDARAP 倒写。
3. 结果与阅读顺序明文 `z340_plaintext.txt` **逐字一致**。

**“H 移位”的独立确认**：只用第 1 段的规则去读第 2 段时有 8 行不符。穷举“把该行任一符号移到任一列”的全部 17 × 17 种可能，**只有“第 17 列 → 第 4 列”这一种**能让第 2 段与已知明文完全一致，与破解者的描述相同。

## 4. 统计复现

| 统计量 | 本项目计算 | 社区公布值 |
|---|---|---|
| Z340 周期 1 双字母重复 | 25 | 25 |
| Z340 周期 19 双字母重复 | 37（1–40 各周期中最大） | 37 |
| 周期 19 置换检验（20,000 次打乱） | 打乱均值 17.81 ± 3.64，z = 5.27，没有一次 ≥ 37（p < 5×10⁻⁵） | — |
| 周期 1 置换检验 | z = 1.37，p ≈ 0.11（不显著） | — |

**补充观察（负面结果）**：只在单段（9×17 = 153 字符）内扫描全部 96 种可遍历的 (dr, dc) 抽取、并以双字母重复数排序时，(1, 2) **并不排在第一**（第 1 段并列第 4，第 2 段不在前 5）。153 字符上的双字母统计噪声太大，不足以单独锁定换位方案。这与历史一致：2020 年的突破靠的是对约 65 万种候选换位**逐一跑求解器**，而不是单靠双字母统计。对 Z13 / Z32 这样更短的密文，统计量的噪声只会更大。

## 5. 盲解复现

不使用任何明文信息，仅凭求解器 + 语言模型解密。8 进程并行，种子 1。

| 语言模型 | 来源 | 说明 |
|---|---|---|
| 内置 4-gram | Python 标准库文档（约 165 万字母） | 无需下载；技术英语，偏弱 |
| AZdecrypt 5-gram（beijinghouse v7） | 数 TB 语料编制，AZdecrypt 附带 | CC BY-NC 4.0，**不纳入本仓库**，需自行下载到 `models/`（见 README） |

### 5.1 Z408

| 模型 | 设置 | 最佳解准确率 | 用时 |
|---|---|---|---|
| 内置 4-gram | 8 次重启 × 2000 次扫描 | 83.8–85.3%（前两名） | 25 s |
| AZdecrypt 5-gram | 8 次重启 × 1500 次扫描 | **100.0%**（8 次重启全部收敛到同一解） | 15 s |

内置模型的最佳解前 5 行（准确率 85.3%）：

```
ISIDEDITSINGPEOPT      ← I LIKE KILLING PEOPLE（部分 K、L 被误作 D、S、T）
ERECAUSEITISSOMUC      ← BECAUSE IT IS SO MUCH
HFUNITISMOREFUNTH      ← FUN IT IS MORE FUN TH
ANDINTINGWISDGAME      ← AN KILLING WILD GAME
INTHEFORLESTRECAU      ← IN THE FORREST BECAU
```

内置模型下，最高分解的得分（106.4）略高于真实明文的得分（106.1）——剩余约 15% 的错误来自语言模型本身（技术英语语料中 “KILL”“LIKE” 等词统计不足），而非搜索不充分。换用 5-gram 模型后，求解器得到的正是 Harden 密钥（连同 Zodiac 本人的加密错误），得分 196.3 与真实明文完全相同。

### 5.2 Z340

| 模型 | 输入 | 设置 | 最佳解得分 | 准确率 |
|---|---|---|---|---|
| 内置 4-gram | 去除换位 | 8 × 2000 | 105.2 | 25%（失败；真实明文仅 100.5，低于错误解） |
| AZdecrypt 5-gram | **去除换位（已发表方案）** | 16 × 2000 | **194.6** | **95.0%** |
| AZdecrypt 5-gram | 原顺序（不去除换位） | 16 × 2000 | 168.8 | 9.7% |

5-gram 模型、去除换位后的最佳解（准确率 95.0%）：

```
IHOPEYOUAREHAVING
LOTSOFFANINTRYING
TOCATCHMETHATWASN
TMYONTHETVSHOWWHI
CHBRINGOUPAJOINTA
BOUTMEIAMNOTAFRAI
DOFTHEGASCHAMBERB
ECAASKITWILLSENDM
KZOJAXALLCEALLTHE      ← 实为 ETOPARADLCEALLTHE：此处几个低频符号未解对
...
```

- 16 次重启中仅 1 次收敛到正确解（得分 194.6，其余最高 173.6），说明 Z340 的搜索难度远高于 Z408，需要足够多的重启。
- 剩余 5% 错误集中在只出现 1–2 次的低频符号上；该解的得分（194.6）甚至高于带有 Zodiac 本人错误的真实明文（190.8）。
- 同一模型下，去除换位与原顺序的最佳得分相差约 26 分：**求解器得分可以区分正确换位与错误换位**。

### 5.3 “候选换位 × 求解器”扫描（小规模重现 2020 年的搜索流程）

脚本：`scripts/z340_transposition_scan.py`。对第 1、2 段施加全部 96 种可遍历的 (dr, dc) 抽取（第 3 段按行读取），外加原顺序，共 97 个候选；**不做 LIFEIS / H 移位 / 倒写等异常修正**（模拟破解者尚不知道这些异常时的状态）。

| 阶段 | 预算 | 第 1 名 | 第 2 名 | 备注 |
|---|---|---|---|---|
| 粗扫（97 个候选） | 8 次重启 × 600 次扫描 | **(1,2)** 171.45（z = 3.1） | (8,15) 170.99 | 候选均值 166.29 ± 1.64；(8,15) 正是 (1,2) 的逆向路径 |
| 精扫（粗扫前 5 名） | 16 次重启 × 2000 次扫描 | **(1,2)** 172.21 | (4,2) 171.19 | 原顺序 168.83 排第 5 |

结果：
1. 两个阶段中 **(1,2) 都排第 1**，而且粗扫的前两名是同一条路径的正反两个方向。
2. 但优势很小，且在不修正异常、预算有限的情况下，求解器**没有**解出可读明文（172 分 vs 修正异常后的 194.6 分）。第 2 段的 H 移位会让其后的抽取顺序整体错位，使近一半密文无法贡献有效信号。
3. 这与历史相符：破解者在 (1,2) 候选上先看到第 1 段出现 “HOPE YOU ARE”“TRYING TO CATCH ME” 等片段，之后才逐一找出 LIFEIS、H 移位和末两行倒写。**“排名第一但信号微弱”正是真实搜索中必须人工跟进的阶段。**

结果文件：`results/z340_transposition_scan.csv`、`results/z340_transposition_refine.csv`。

## 6. 对后续工作的启示

1. **语言模型的质量决定真实明文能否排在第一。** 内置模型连 Z340 的真实明文都认不出，5-gram 模型则能完整复现两份已解密文。后续所有实验默认使用强模型，并同时报告“真实明文的得分排名”。
2. **只看统计量不够。** 153 字符的双字母统计已无法锁定换位方案；13 / 32 字符更不可能。Z13 / Z32 的换位假设必须用“求解器得分 + 零假设对照”来检验（方向 D）。
3. **作者错误与异常必须显式建模。** 一处 H 移位就足以把正确换位的得分从 194.6 压到 172，接近噪声水平。对 Z13 / Z32 这样的短密文，一处错误的影响只会更大。
4. **需要足够多的重启。** Z340 在 16 次重启中只成功 1 次；短密文的搜索景观更平坦，更需要系统报告成功率而不是单次结果。
